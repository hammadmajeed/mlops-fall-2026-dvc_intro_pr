# DVC pipeline + PR model review lab

This is a complete reproducible **generate → train → evaluate** example.
It produces `metrics.json`, a ROC CSV plot, and a pull-request report containing
an ROC overlay PNG, numeric deltas, and a blocking regression gate.

## First run (create the baseline main branch)

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
git init -b main
dvc init
dvc repro
python -m pytest -q
git add .gitignore .dvcignore .dvc/ dvc.yaml dvc.lock params.yaml \
  requirements.txt src tests .github metrics.json plots/roc.csv README.md
git commit -m 'Baseline model and DVC pipeline'
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPO.git
git push -u origin main
```

**Important**: `dvc init` must run inside the student's freshly created Git repo;
this distribution intentionally does not contain a `.git/` or `.dvc/` directory.
`data/` and `models/` are reproducibly generated by the pipeline, so the classroom
lab needs no DVC storage credentials. For a production dataset, add `dvc remote`,
push it with `dvc push`, and configure CI access using scoped secrets.

## Create a candidate PR

```bash
git switch -c experiment/shallow-forest
# Edit params.yaml: train.max_depth: 5 -> 1
dvc repro
dvc metrics diff main
dvc params diff main
dvc plots diff main
python -m src.pr_report --base-ref main  # may exit 1: this is expected for a regression
# inspect report.md and reports/roc_comparison.png
git add params.yaml dvc.lock metrics.json plots/roc.csv
git commit -m 'Experiment: shallow random forest'
git push -u origin experiment/shallow-forest
```

Open GitHub → **Pull requests** → **New pull request**: base `main`, compare
`experiment/shallow-forest`. The `DVC Model Review` workflow trains, checks
reproducibility, posts the metrics and ROC graph via CML, and blocks merge on a
metric regression. GitHub repository Settings → Branches/Rulesets → require
`review` status check before merge. For demo purposes use a same-repository branch;
fork PR workflows normally cannot post comments due to restricted token permissions.

To demonstrate a successful case, create a second branch from `main`, set
`train.n_estimators: 100 -> 120`, reproduce and push. Passing the quality check
means **eligible for review**, not automatically safe to deploy.

## Pipeline and metrics

```bash
dvc dag
dvc metrics show
dvc metrics diff main
dvc plots show
dvc plots diff main
```

Generated `metrics.json` and `plots/roc.csv` are tracked **in Git** as human-reviewable
small outputs (`cache: false`), while model and intermediate data are managed by DVC.
The base revision's metrics and ROC file must exist on `main` for comparison.

## Security and limitations

- This lab is for trusted same-repository student branches. `pull_request_target`
  must not be used to execute unchecked contributor code with a write token.
- `pickle` model loading is safe only for the artifacts generated by trusted code.
- Classifier metrics alone are not a full production release criterion.
- CML requires write permission to PR comments and access to its image publication
  mechanism; the GitHub Actions job's status fails if the report cannot be posted.
- ML dependencies are bounded, not fully locked. For bitwise repeatability,
  additionally lock the environment (e.g., `uv.lock`) and runner image.
